herdr × Git Worktree：多 Agent 并发开发环境实践

💡 Read English Version (英文版)

并发跑多个 Coding Agent 时，难点不在“把它们跑起来”，而在三件事：文件互踩、状态盲区、会话脆弱。本文从 git worktree 和 herdr 两块地基讲起，给出我实际在用的项目级并发开发环境设计：一个仓库多份 worktree、Agent 按任务现场指定、主仓统一合并收口。环境基于 herdr 0.9.5 / macOS，核心概念与命令跨平台通用。

1. 多 Agent 并发的三堵墙

当你同时开启 5 个终端窗口并发跑 Coding Agent 时，很快就会陷入“打地鼠”式的混乱：A 窗口的 Agent 正在改公共模块，B 窗口的 Agent 顺手把同一个文件覆盖了；C 窗口的 Agent 卡在危险命令权限确认弹窗上静默等了半小时，你直到切过去才发现；更致命的是手滑关掉一个终端窗口，跑了一半的重构连同上下文当场灰飞烟灭。

把这些痛点拆开，背后是三堵基础设施之墙：

问题 典型现象 底层根因
文件互踩 两个 Agent 同时改一个仓库，A 改到一半被 B 覆盖或触发构建报错 多个并发进程共享同一个物理工作目录（Working Tree）
状态盲区 谁在思考、谁卡在权限确认、谁已跑完，只能挨个切窗口肉眼轮询 传统终端复用器只管转发 PTY 字节流，不认识窗格里跑的是 Agent
会话脆弱 终端窗口误关或 SSH 闪断 = Agent 进程收到 SIGHUP 死亡，现场全没 Agent 进程直接挂在前台窗口的 PTY 会话上，缺乏后台守护层

解法不需要重造轮子，两块现成工具分层补齐：git worktree 管物理文件隔离，herdr 管 Agent 状态感知与后台会话存活。把它们按一套严密的工程纪律组合起来，就是完整的多 Agent 并发开发环境。

2. 地基一：Git Worktree——一个仓库，多个工作树

2.1 它解决什么问题

让两个 Agent 并发修改同一个代码仓库，常见的三种土办法都有明显代价：

  • Clone 多份独立仓库：磁盘占用翻倍，本地提交互不可见，分支同步必须绕道远端 origin 中转；
  • 同目录来回 git checkout：天然串行，根本无法并发；
  • Stash 舞蹈：git stash → 切分支 → 修改 → git stash pop，冲突概率随并发数指数级上升。

git worktree 是 Git 官方给出的标准答案：同一个 .git 对象库，挂载多个独立的工作目录（Checkout）。每份工作树拥有独立的物理目录和当前分支，但底层共享同一个 .git/objects 与引用库——任何一份工作树里 git commit 的代码，其他工作树在同一秒内即可直接看见、直接 merge 或 rebase，零网络同步成本。

2.3 两条铁律

  1. Worktree 内只 commit，严禁 push：各工作树只负责在自己的任务分支上往前推进本地提交；合并与远端推送统一回到主仓库执行。若允许多个工作树各自向远端乱 push，远端分支历史与 CI 流水线会迅速陷入互相踩踏。
  2. 合并统一在主仓收口：在主仓库（固定停留在 master/main）逐条执行 git merge --no-edit <branch>；遇到冲突在主仓统一裁决，保留双方有效改动，严禁在工作树里用 --ours / --theirs 一刀切抹掉他人代码。

2.4 必踩的第一坑：gitignored 文件不会自动跟过来

.env 环境变量、本地私钥、未入库的 Agent 本地配置（如 .claude/settings.local.json）这类被 .gitignore 忽略的文件，在新 worktree 检出后默认不存在。如果不处理，新工作树里的项目一跑就会因为缺环境变量或丢 MCP 配置而报错。后文 §4.3 会给出主仓一键广播脚本的落地解法。

3. 地基二：herdr——认识 Agent 的终端复用器

3.1 核心定位

herdr 是一个用 Rust 编写的专为 AI Agent 设计的单二进制终端多路复用器。与传统仅转发字节流的终端工具不同，它做对了一件关键的事——原生理解窗格（Pane）里跑的是不是 Coding Agent，以及这个 Agent 当前处于什么生命周期状态。

它的底层采用 C/S 架构：后台 herdr server 守护进程持有所有窗格的 PTY 文件描述符，前台 TUI 只是附着（Attach）上去的渲染视图。这是它一切持久化能力的根源：前台终端窗口随时可以关掉，Agent 进程始终稳稳活在后台 server 里。

3.2 核心概念模型

概念 工程含义
server 后台守护进程，持有本机全部 PTY 会话；一个 server 可同时挂载任意多个代码仓库
workspace 项目级容器，通常一个 Git 仓库对应一个 workspace；与你在哪个目录敲 herdr 无关
pane 终端窗格；既可以跑普通交互式 Shell，也可以托管各类 Coding Agent
agent 被 herdr 识别并追踪的 Agent 进程，通过 --kind 指定类型（claude / codex / pi / opencode / antigravity-cli 等，0.9.5 版本共内置 24 种）
state Agent 的实时生命周期状态：working / blocked / idle / done

3.3 三层递进价值

  1. 会话持久化（底座价值）：MacBook 合盖休眠、SSH 网络闪断、手滑关掉终端窗口，后台 Agent 任务照常运行，重连后敲 herdr 一秒恢复完整分屏现场。
  2. 全局状态看板（核心差异化价值）：左侧边栏实时渲染每个项目、每个窗格内 Agent 的状态灯（尤其是黄灯 blocked 与绿灯 done），彻底消灭切窗口轮询的心智负担。
  3. Agent 自编排（高阶涌现价值）：为 Agent 注入官方 herdr Skill 后，窗格里的主 Agent 可以自己调用 CLI 分屏、拉起子 Agent、派发子任务、阻塞等待完成并读取产出——这是传统终端脚本极难做到的闭环。

避坑认知：不要把 herdr 单纯当成“多 worktree 启动器 + 完成提醒工具”。Worktree 隔离只是按需开启的辅助能力，上面三层价值才是主体；而且如果跳过 herdr integration install 步骤，状态识别会退化为脆弱的“屏幕文本正则猜测”，准确率大打折扣。

3.5 交互方式与核心键位

herdr 采用鼠标一等公民设计：点击切换窗格焦点、拖拽分割线调整大小、右键呼出窗格操作菜单、鼠标拖选直接复制文本，全程无需记键位即可流畅操作。

键盘操作则沿用经典的 Prefix 模式（默认前缀键为 Ctrl+B——注意是先按一下 Ctrl+B 松开，再按后续动作键，而非一直按住）：

快捷键 作用说明
prefix + v 向右垂直分屏（新建右侧窗格）
prefix + - 向下水平分屏（新建下方窗格）
prefix + c 在当前 Workspace 内新建 Tab
prefix + Shift+G 交互式新建 Git Worktree
prefix + ? 弹出实时快捷键全集浮层
prefix + q Detach 脱离当前视图（后台任务继续运行；直接关终端窗口效果相同）

持久化体感：随时按 prefix + q 或直接 Cmd+W 关掉终端窗口 → 在任意目录重新输入 herdr 即可无损附着回原现场。只有显式执行 herdr server stop 才会真正终止后台守护进程与所有窗格。

3.6 状态灯语义与注意力转变

状态灯 生命周期含义 你的响应策略
working 正在思考、推理或执行工具调用 忽略，让它自己跑
blocked 卡在危险操作权限审批或交互式提问，等你按键 立即切过去处理（最高优先级）
idle 回合已结束且你已查看过现场，处于待命状态 可随时派发下一个任务
done 任务刚刚跑完，且你还没有切过去看过结果（聚焦该窗格后自动归为 idle） 抽空切过去验收成果

这套状态机直接重塑了日常开发心流：你可以同时在三四个项目里挂着 Agent 跑任务，自己专心写核心设计或看文档；眼角余光扫一眼侧边栏——平时全当它们不存在，只在亮起 blocked 或 done 时介入。

3.7 宿主终端选型与配置：为什么定案 Tabby

herdr 本身是跑在终端模拟器里的 TUI 程序，宿主终端（Host Terminal）的事件透传能力直接决定了日常操作顺不顺手。

在我的高频工作流里，有两条不可妥协的硬指标：

  1. 全鼠标右键管理窗格：分屏、关闭、缩放（Zoom）全部走鼠标右键菜单；
  2. Cmd+V 剪贴板直贴图片：把报错截图、架构草图直接 Cmd+V 粘贴进 Claude Code 等多模态 Agent。

围绕这两条硬指标实测主流 macOS 终端后，结论非常明确：

宿主终端 Cmd+V 贴图进 herdr 内 Agent 鼠标右键与特性支持 实测结论
Tabby (Electron) 全链路畅通（粘贴在应用层消化，不被 PTY 吞掉） 关闭应用层右键菜单后，100% 透传给 herdr 主力定案（零损失）
Ghostty 断裂（Cmd+V 只送达裸字符 "v"，无论是否经 herdr 均贴不了图） 原生支持 Kitty 键盘协议与鼠标透传 贴图刚需下一票否决
Warp 受限于自有输入框模型 Block 输入模型劫持鼠标与按键事件，与 TUI 复用器冲突 不兼容
macOS Terminal.app 不支持富媒体剪贴板透传 缺乏 Kitty Keyboard Protocol，修饰键残缺 不推荐

Tabby 零摩擦配置三步走：

  1. 打开 Tabby Settings → Application，找到 “Show menu on right click” 并将其关闭（对应配置文件中的 rightClick: 'off'）。关闭后，在窗格内点击右键将直接呼出 herdr 原生分屏菜单；
  2. 字体与主题推荐：Maple Mono NF CN 搭配 Catppuccin Mocha 配色；
  3. 给纯键盘流用户的补充建议：如果你不依赖 Cmd+V 贴图、而是重度依赖复杂键盘快捷键，宿主终端需满足三项条件——原生鼠标事件透传、支持 Kitty Keyboard Protocol（建议 Kitty ≥ 0.33 或 Alacritty ≥ 0.15.0，旧版 Alacritty 存在按键 release 字节重复发送 Bug）、以及在终端设置中开启 Option as Meta。

4.2 五条工程设计原则

  1. Workspace 绑项目，绝不绑 Agent：一个 Git 仓库对应一个 Workspace；多项目并行就是多个 Workspace 并存，彼此隔离。
  2. Worktree 只为并发隔离而生：单 Agent 改单个项目时直接在主仓跑即可，完全用不上 worktree；只有当两个以上 Agent 需要同时修改同一个仓库时才开辟 worktree。

    反面教训：我早期曾按 Agent 种类建目录（比如 myproject-claude、myproject-opencode），结果一旦想在第二个目录里换用 Claude，目录命名就和实际跑的 Agent 错位了。正确认知是：目录只代表“仓库的第 N 号隔离副本（wt-1、wt-2）”，与谁在里面干活毫无关系。

  3. Agent 现场按需指定，目录编号不编码用途：wt-1 只是槽位序号；窗格里今天跑 claude 写功能、明天跑 codex 修 Bug、后天跑 opencode 写测试，全由启动时的命令或 --kind 参数现场决定，目录原地不动。
  4. 主仓只做收口与基线维护：所有 worktree 内部只允许 git commit，严禁执行 git push；分支合并、冲突裁决与远端推送统一回到主仓执行（将 §2.3 铁律固化为环境级约束）。
  5. 未追踪配置从主仓单向广播：.env、本地密钥、MCP 配置等 gitignored 文件以主仓为唯一事实源（SSOT），通过同步脚本一键分发到各 worktree 槽位，彻底填平 §2.4 的坑。

6. 进阶视角：多 Agent 协作的三层正交架构

当并发规模继续扩大时，只靠终端分屏还不够，必须在架构上把控制面、会话层、记忆层彻底解耦：

架构分层 核心承担者 职责边界与工程原语
控制面 (Control Plane) herdr 负责窗格 PTY 生命周期、状态灯感知（working/blocked/done）、进程拉起与 prompt/wait/send-keys 调度。注意：prompt 只是盲传字符串，控制面不理解业务语义
会话层 (Session Layer) 各 Agent CLI 自持 对话上下文按项目目录持久化落盘（如 Claude Code 的 -c 续接最近会话、-r 挑选历史会话、--fork 分叉推演）。换终端宿主绝不丢失对话历史
记忆层 (Memory Layer) 语义记忆库（如 OpenViking） 负责跨会话、跨 Agent 的长期架构决策与踩坑结论沉淀。任何支持**“写入明确 URI 地址 → 跨会话语义检索取回”**的持久记忆系统都可承担此层

核心分层纪律：严禁通过 herdr pane send-keys 在不同 Agent 之间盲传大段上下文文本。正确的协作范式是：控制面只管“活儿在哪个窗格跑、跑完没有”，会话层管“当前任务聊到哪一步了”，而跨 Agent 的知识交接一律走记忆层（Worker 将结论写入明确的记忆 URI 或交接文件，主 Agent 按地址精准读取）。

7. 下班之后：手机远程接管全链路

多 Agent 并发环境跑顺之后的下一个自然诉求是：人离开工位去吃晚饭或在地铁上时，卡在 blocked 权限确认弹窗上的 Agent 谁来点确认？

很多人的第一反应是向日葵、ToDesk 或 VNC 远程桌面——但在 6 寸手机屏幕上缩放拖拽 27 寸桌面、看着全屏 TUI 重绘糊成马赛克，是效率最低的折磨。既然我们要操控的对象本质上是终端会话，最优雅的方式就是回归终端的原生协议：SSH。

这套方案与本文的 herdr 环境天然咬合：

  • 平时手机完全静默：只有当某个窗格里的 Agent 触发 permission_prompt 变为 blocked、或长任务跑完触发 Stop 时，Hooks 脚本才会给手机发一条带项目名的锁屏通知；
  • 掏出手机 10 秒处理：点开 Termius 连上内网 Mac，敲 herdr 瞬间附着回桌面上的完整并发视图，用虚拟方向键切到黄灯窗格按 y 放行，锁屏揣回兜里，Agent 继续往下跑。

📖 完整部署指南：关于云端 frps 与 Mac 侧 frpc（LaunchAgent 开机自愈）的逐行配置、macOS sshd 禁用 PAM 键盘交互认证的安全加固、~/.claude/settings.json 锁屏推送脚本，以及实测必踩的三个大坑，请直接阅读姊妹篇《外网连进内网 Mac：frp + SSH + Termius 手机远程全链路实战》。

8. 实战踩坑与排查指南

最后把日常高频使用 herdr 过程中提炼出的关键排障经验整理成清单，供碰到同类症状时按图索骥：

  1. prefix 快捷键怎么按都没反应：
    herdr 的前缀键（默认 Ctrl+B）采用严格的两段式触发——先按下 Ctrl+B 并完全松开手指，再按后续动作键（如 v、c、?）。如果习惯性一直按住 Ctrl+B 不放再去按动作键，在任何终端里都会100% 失败。

  2. 使用尚未内置的 Agent（如 CodeBuddy）时如何点亮状态灯：
    以 codebuddy 为例，herdr 0.9.5 的内置枚举、屏幕正则清单与 integration install 列表里都没有它；且官方文档明确说明 Override manifest 只能微调已内置 Agent 的匹配规则，无法凭空注册新 Agent 类型。
    正解是直接走官方一等公民路径——利用 Agent 自身的 Hooks 调用 herdr pane report-agent 主动上报：

    因为 herdr 窗格会自动向子进程注入 HERDR_PANE_ID 环境变量，只需在 Agent 的配置文件中将 6 个标准生命周期事件映射到上述命令即可完美点亮状态灯：

    • SessionStart → --state idle
    • UserPromptSubmit → --state working
    • Stop → --state idle
    • Notification (permission_prompt) → --state blocked
    • Notification (idle_prompt) → --state idle
    • SessionEnd → herdr pane release-agent "$HERDR_PANE_ID"

  3. herdr machine add 接入远端机器的两个暗坑：

    • 默认选项陷阱：当远端机器已有运行中的 herdr server 时，CLI 会交互式提问“是否停掉并替换远端 server？ [y/N]”。注意默认回车是 N（直接放弃保存配置），必须显式输入 y 回车才能完成注册；
    • 守护进程打架：如果远端机器之前自己配过 LaunchAgent 或 systemd 常驻守护 herdr server，在执行替换动作时会发生进程争抢。接入 machine 模式前，应先停掉自定义的守护配置，把 server 生命周期交还给 herdr 自身管理。

  4. 状态判定与全屏 TUI 输出读取的边界：

    • unknown 不代表跑完：状态显示 unknown 说明 Agent 仍在运行但当前屏幕特征无法归类，可执行 herdr agent explain --json 查看底层状态机给出的具体判定依据；
    • CLI agent read 不会消除 done 绿灯：只有人类在 TUI 界面中真正将焦点切入该窗格，done 状态才会归位为 idle；
    • 备用屏（Alternate Screen）截断问题：像 Claude Code 这类全屏 TUI 程序渲染在终端备用屏上，超长回复不会进入普通终端滚动缓冲区（Scrollback Buffer），导致 herdr agent read 只能抓到当前一屏的尾部。在自动化 Fan-out 编排中，务必在 Prompt 里要求子 Agent 将完整分析报告写入指定的 Markdown/JSON 文件，主 Agent 直接读文件而非抓屏幕。

  5. 日常日志与配置热重载入口：

    • 运行日志路径：~/.config/herdr/herdr*.log
    • 查看前后端连接与版本状态：herdr status（或 herdr status server / herdr status client）
    • 导出全量默认配置参考：herdr --default-config
    • 修改 ~/.config/herdr/config.toml 后无需重启 server，执行 herdr server reload-config 即可毫秒级热生效。
