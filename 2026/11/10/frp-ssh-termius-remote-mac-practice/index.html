外网连进内网 Mac：frp + SSH + Termius 手机远程全链路实战

实战基线：macOS（Apple Silicon）+ frp 0.72.0 + 云端 Linux VPS（Debian 12）+ Termius（iOS / Android 双端）+ herdr 常驻会话层。

1. 问题：人在外面，Mac 在家里

那台 Mac 上跑着你想随时回去的东西——编译到一半的任务、一组开发服务、十几个并发运行的 AI coding agent 会话，或者就是一个不想中断的终端环境。人在外面时选择只有两个：回去，或者远程。

多数人的第一反应是远程桌面（ToDesk / 向日葵 / RustDesk），在手机上看 Mac 屏幕。能用，但体验是灾难级的：用 6 英寸手机屏幕操控 27 英寸桌面，鼠标指针漂移、字小到看不清，终端 TUI 的全屏重绘在视频流压缩下糊成一团。你要操控的根本不是“Mac 的屏幕”，而是“那几个终端会话”——那就该用终端的原生方式解决：SSH。

拦路的是网络现实：家里或办公室的 Mac 蜷在 NAT 后面，没有公网 IP，手机从哪连？本文用一台最低配云 VPS + frp 解决这一跳，配合 Termius 与常驻会话层 herdr 打通“世界任何角落 → 你的 Mac shell”全链路——从选型、部署、加固、通知推送到三个实测排障大坑，全部可复现。

2. 选型：为什么是 frp + SSH

动手前我把市面上的远程接管路线完整过了一遍（2026-11 实测状态）：

最终锁定 frp + SSH + 常驻会话层 的三个决定性理由：

  1. 无差别接管“一切已在跑的存量会话”。Mac 侧配一层常驻会话层（本文选用专为 AI Agent 设计的终端多路复用器 herdr），由后台守护进程持有全部 PTY：SSH 断连多少次，进程原地活着，重连即恢复现场。这条路不挑终端里跑的是什么——编译任务、长服务、Claude Code、OpenCode、任何 shell 全部适用。Happy 与 Paseo 都要求会话从头由它们启动，桌面上跑了一半的存量任务接管不了。
  2. 模型端点完全解耦。国内大量开发者走 Anthropic 兼容中转端点（企业网关、智谱 GLM、火山方舟 Ark 等），而 Claude 官方 Remote Control 硬性要求直连 api.anthropic.com 且不得残留自定义 ANTHROPIC_* 环境变量，中转用户直接出局。SSH 隧道工作在传输层，上层 Agent 走什么 API 端点与它完全正交。
  3. 已有 VPS 即零边际成本。frp 是久经验证的内网穿透方案（GitHub 8 万+ Star），一台最低配云主机即可承载，不引入重型守护进程。

3. 架构：三个正交平面

整套体系拆成三个正交平面，每个平面只解决一件事：

  • ① 隧道平面（frp）——够得着：Mac 在 NAT 后没有公网 IP，由 Mac 上的 frpc 主动向云 VPS 的 frps :7000 拨出建立长连接隧道；手机 SSH 连 VPS 的 :6022 入口端口，流量即被透明转发至 Mac 本机的 127.0.0.1:22。
  • ② 会话平面（herdr）——接得上：后台 server 进程持有所有窗格（pane）的伪终端 PTY。手机进电梯断网、切蜂窝网络或主动退出 App，任务都在 Mac 后台继续跑；重连后敲一行 herdr 立刻回到断线前那一秒。
  • ③ 通知平面（Bark / ntfy）——想起来：当 Agent 卡在权限确认弹窗（blocked）或任务执行完毕（Stop）时，通过本地 Hook 一发 curl 把告警推上手机锁屏，无需隔几分钟掏手机盲查。

6.3 日常使用教程：接管会话、审批权限与无损脱离

连进 Mac shell 只是第一步，真正的日常操作流围绕常驻会话层展开：

  1. 一键附身回到现场：
    在终端直接输入 herdr 回车，屏幕上所有项目的并发 Agent 窗格与侧边栏状态灯原样呈现。
  2. 在手机上切换窗格与处理 Agent 权限弹窗：
    • 触屏直点：Termius 原生支持终端鼠标协议（Mouse Reporting），手指直接点击目标窗格即可聚焦，点击 herdr 侧边栏标红（blocked）的項目即可切过去看是谁在等确认。
    • 审批弹窗：利用 Termius 键盘上方扩展键条的 ↑ ↓ 方向键与 Enter 键，一秒完成 Claude Code / OpenCode 的工具执行授权，或直接语音输入追发下一条 Prompt。
    • 视野调节：分屏较多时将手机横屏，双指捏合实时缩放字号。
  3. 安全脱离（Detach）与断网恢复：
    • 处理完毕准备收起手机时：点 Termius 扩展键条的 CTRL（高亮锁定）→ 点字母 b（发送前缀键 Ctrl+b）→ 再点 q（herdr 脱离键）。此时退回普通 shell，后台进程毫发无损。
    • 暴力断连零损失：哪怕忘记脱离直接划掉 Termius App、锁屏或进地铁断网，也完全不用担心——PTY 由 Mac 本机的 herdr server 进程持有，下次重连敲 herdr 依然原地续接。

我的日常场景是在 Mac 上用 herdr 同时跑十几个 AI coding agent，手机敲一个 herdr 就能巡检全部窗格——这套多 Agent 并发环境搭建详见姊妹篇《herdr × Git Worktree：多 Agent 并发开发环境实践》。

9. 踩坑实录：三个价值一下午的排障大坑

整套配置本身半小时就能跑通，但我实测时多花了好几个小时，全折在下面三个极具迷惑性的假象里。它们共同指向一条底层排障铁律：当排障陷入死胡同时，先怀疑自己的观测手段。

9.1 坑一：本机测公网端口，全是假阳性

  • 失真现象：在 Mac 本机执行 nc -zv <VPS_IP> 6022 探测远端端口，无论 VPS 上 frps 是否启动，永远秒回 Connection to ... 6022 port [tcp/*] succeeded!，但真正发起 SSH 连接却立刻卡死。
  • 底层根因：Mac 上开着代理工具的 TUN 模式（Clash / mihomo 系），虚拟网卡通过 fake-ip 与透明劫持接管了全部出站 TCP SYN 包——三次握手在本地内核就被 TUN 协议栈直接 ACK 了，nc 看到的“连接成功”只是本机代理栈回的假象，数据包甚至还没走出网卡。
  • 正确验证姿势：开启了 TUN 代理的主机上，一切 nc / telnet 端口连通性探测结果均不可信。外部可达性测试必须从一台干净的外部云主机发起，或直接用切到 4G/5G 蜂窝网络的手机 Termius 实测。

9.2 坑二：VPS 回环路径上的 sshd 静默超时

  • 失真现象：为了快速验证隧道，我登录到 VPS 上执行 ssh -p 6022 user@127.0.0.1（本机连本机转发口）。结果 TCP 握手秒通、frps/frpc 日志显示代理通道已建立，但 SSH 握手挂起 4 秒后超时断开，连一个字节的 SSH-2.0-OpenSSH Banner 都收不到。同时刻在 Mac 本机测 nc 127.0.0.1 22 却秒回 Banner。
  • 排查弯路：先后怀疑并逐一排除了 frp 版本差异、TLS 加密开关、连接池耗尽、macOS sshd 源地址惩罚（PerSourcePenalties）与 MaxStartups 限制；甚至在 Mac 上临时起了个 Python 回声服务挂进同一条隧道对照——回声服务秒通，唯独 sshd 静默。
  • 底层真相：这是 VPS 本机回环路径（Loopback）特有的边界现象。当我换用另一台外部云主机从公网连 <VPS公网IP>:6022 时，第一次尝试就毫秒级弹出 SSH Banner 并成功登录。我在“服务器上自己连自己”这条真实用户永远不会走的路径上白白消耗了几个小时。
  • 正确验证姿势：测试路径必须 1:1 复刻真实客户端路径。真实流量从外部公网网卡进来，验证就必须从外部公网发起。

9.3 坑三：云安全组的“隐形墙”

  • 失真现象：在 frps.toml 里随手挑了个端口，VPS 上跑 ss -tlnp 看到 frps 正常监听，frpc.log 也打印 start proxy success，便想当然认为公网已经通了——直到从外部云主机探测才发现 SYN 包被静默丢弃。
  • 底层根因：云主机的安全组（Security Group）工作在宿主机虚拟化层，位于 Linux 内核 iptables / nftables 与 ss 视野之外。部署前先去云控制台确认已放行的端口区间，让 allowPorts 与 remotePort 向安全组对齐，能直接省掉一整轮抓包排障。

(附注：macOS 默认没有 GNU timeout 命令，写自动化探测脚本时若用 timeout 5 ssh ... 会因找不到命令静默失败；可用 ssh -o ConnectTimeout=5 原生参数替代，或 brew install coreutils 后用 gtimeout。)

10. 生产验收与安全核对清单

上线前按序过一遍以下 6 项，全绿即可长期免维护运行：

  1. VPS 监听检查：ss -tlnp | grep -E '7000|6022' 确认控制面与入口端口均处于 LISTEN。
  2. Mac 隧道检查：tail ~/.config/frp/frpc.log 确认出现 login to server success 与 [mac-ssh] start proxy success。
  3. 重启自愈验证：重启一次 Mac，不人工干预，确认 frpc 由 LaunchAgent 自动拉起并重连 VPS。
  4. 手机接管闭环：手机切蜂窝网络 → Termius 免密连入 → 敲 herdr → 给正在运行的 Agent 发送一条指令并确认响应。
  5. 双端会话同步：手机 Ctrl+b q 脱离后，在 Mac 桌面终端敲 herdr 确认同一现场无缝衔接。
  6. 密码爆破免疫验证：从外部机器执行 ssh -o PubkeyAuthentication=no -p 6022 <用户>@<VPS_IP> true，确认返回 Permission denied (publickey)。
安全控制项 落地措施 核心防御目标
frp 鉴权凭据 openssl rand -hex 24 生成 48 位随机串 防止弱口令导致 VPS 沦为公共跳板
端口绑定范围 allowPorts = [{ single = 6022 }] 阻止客户端越权在 VPS 上暴露额外端口
配置文件权限 服务端与客户端均执行 chmod 600 *.toml 防止本机非授权进程读取明文 token
SSH 密钥策略 Ed25519 算法，一机一钥，行尾标注设备名 私钥永不出手机，设备丢失可按行精准吊销
密码通道焊死 PasswordAuthentication no + KbdInteractiveAuthentication no 彻底消除公网端口被字典爆破的可能

11. 演进方向

  • 第二操控面（笔记本 / iPad 远程接管）：在随身轻薄本上只需加 4 行 ~/.ssh/config 别名即可同样穿透接入；如果 Mac 跑的是 herdr，还可以直接运行 herdr --remote <ssh别名>，把本地终端变成远端 Mac herdr server 的原生瘦客户端。
  • 更强网络隔离（WireGuard / STCP）：若希望连 6022 端口都不对公网扫描器暴露，桌面端之间可切换为 frp stcp（Secret TCP）模式；含手机端接入时可在 VPS 上额外部署 WireGuard 组网，将 SSH 入口完全收入虚拟私网内部。
