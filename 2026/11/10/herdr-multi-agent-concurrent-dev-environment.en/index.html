herdr × Git Worktree: A Practical Multi-Agent Concurrent Development Environment

When running multiple coding agents concurrently, the hard part is not spinning them up—it is surviving three structural bottlenecks: file collisions, state blindness, and fragile sessions. Starting from two foundational primitives—git worktree and herdr—this article presents the production project-level concurrent development environment I run daily: multiple isolated worktrees backed by a single repository, on-demand agent assignment per task, and centralized merge convergence in the main repository. While verified on herdr 0.9.5 / macOS, the architecture and commands apply across platforms.

1. The Three Walls of Multi-Agent Concurrency

Spin up five terminal windows to run coding agents in parallel and you quickly descend into a game of whack-a-mole: the agent in Window A is refactoring a shared module while the agent in Window B silently overwrites the exact same file; the agent in Window C has been stalled on a dangerous-command permission prompt for thirty minutes, which you only discover when you manually alt-tab into it; worst of all, accidentally closing a terminal window kills a half-finished refactoring session along with its entire live execution state.

Deconstructing these failure modes reveals three underlying infrastructure walls:

Bottleneck Typical Symptom Root Cause
File Collisions Two agents edit the same repo simultaneously; Agent A’s half-written changes are overwritten by Agent B or break the build Multiple concurrent processes share a single physical working directory (Working Tree)
State Blindness You can only tell which agent is thinking, blocked on a prompt, or finished by manually cycling through windows Traditional terminal multiplexers only forward raw PTY byte streams and have no concept of an “agent”
Fragile Sessions Closing a terminal window or dropping an SSH connection sends SIGHUP, killing the agent process and wiping the workspace Agent processes are attached directly to the foreground window’s PTY session without a persistent daemon layer

You do not need to reinvent the wheel to solve this. Two off-the-shelf tools address the problem at orthogonal layers: git worktree handles physical filesystem isolation, while herdr handles agent state awareness and background session persistence. Combined under a strict set of engineering disciplines, they form a complete multi-agent concurrent development environment.

2. Foundation I: Git Worktree — One Repository, Multiple Working Trees

2.1 What It Solves

When two agents need to modify the same repository concurrently, the three common workarounds all carry steep penalties:

  • Cloning multiple independent copies: Doubles disk usage, hides local commits from other copies, and forces every synchronization through the remote origin;
  • Switching branches in the same directory (git checkout): Inherently serial—true concurrency is impossible;
  • The git stash dance: git stash → switch branch → edit → git stash pop, where merge conflict probability scales exponentially with concurrency.

git worktree is Git’s native architectural answer: a single .git object database mounted across multiple independent working directories (checkouts). Each worktree has its own physical directory and checked-out branch, while sharing the underlying .git/objects store and refs—any commit made in one worktree is instantaneously visible to every other worktree for merging or rebasing at zero network synchronization cost.

2.2 Essential Commands at a Glance

2.3 Two Iron Rules

  1. Commit locally inside worktrees; never push from them: Each worktree is responsible solely for advancing local commits on its dedicated task branch. Merging and remote pushing are performed exclusively from the main repository. Allowing multiple worktrees to push independently quickly corrupts remote branch history and triggers colliding CI runs.
  2. Converge all merges in the main repository: Keep the main repository anchored on master/main and run git merge --no-edit <branch> sequentially. Resolve any conflicts centrally in the main repo while preserving valid changes from both sides—never use --ours or --theirs inside a worktree to blindly wipe out parallel work.

2.4 Trap #1: gitignored Files Do Not Carry Over Automatically

Files ignored by .gitignore—such as .env environment variables, local private keys, and untracked local agent configurations (e.g., .claude/settings.local.json)—do not exist in newly created worktrees. Left unaddressed, builds and agents inside a fresh worktree will immediately fail due to missing environment variables or dropped MCP servers. Section 4.3 provides a one-command broadcast script from the main repository to eliminate this friction.

3. Foundation II: herdr — An Agent-Aware Terminal Multiplexer

3.1 Core Positioning

herdr is a single-binary terminal multiplexer written in Rust purpose-built for AI coding agents. Unlike traditional terminal tools that merely forward raw PTY byte streams, it gets one critical abstraction right—it natively understands whether a pane is running a coding agent and tracks that agent’s exact lifecycle state.

Under the hood, it uses a client/server architecture: a background herdr server daemon owns the PTY file descriptors for all panes, while the foreground TUI is merely an attached rendering view. This separation is the source of its persistence—you can close the terminal window at any time while your agent processes continue running undisturbed inside the background server.

3.2 Core Domain Model

Concept Engineering Definition
server The background daemon owning all local PTY sessions; a single server hosts any number of repositories simultaneously
workspace A project-level container, typically mapped 1:1 to a Git repository; independent of the directory from which you invoke herdr
pane A terminal split pane capable of running either a standard interactive shell or a managed coding agent
agent An agent process recognized and tracked by herdr, specified via --kind (claude / codex / pi / opencode / antigravity-cli, etc.—24 built-in kinds as of v0.9.5)
state The agent’s real-time lifecycle state: working / blocked / idle / done

3.3 Three Tiers of Value

  1. Session Persistence (Foundational Value): Close your MacBook lid, survive an SSH drop, or accidentally close the terminal app—your background agent tasks keep running. Run herdr to re-attach in one second with your exact split layout intact.
  2. Global Status Board (Core Differentiator): The left sidebar renders real-time status indicators for every project and agent pane (specifically amber blocked and green done lights), eliminating the cognitive overhead of polling windows.
  3. Agent Self-Orchestration (Emergent Value): Once equipped with the official herdr Skill, a primary agent running inside a pane can invoke the herdr CLI to split new panes, spawn helper agents, dispatch subtasks, block until completion, and harvest results—a closed loop that is notoriously brittle to script with traditional terminal multiplexers.

Common Misconception: Do not treat herdr merely as a “multi-worktree launcher with completion alerts.” Worktree isolation is an opt-in helper feature, whereas the three tiers above are the core engine. Furthermore, if you skip herdr integration install, state detection falls back to brittle screen-scraping heuristics, degrading accuracy significantly.

3.5 Interaction Model & Essential Keybindings

herdr treats the mouse as a first-class citizen: click to focus panes, drag borders to resize splits, right-click to open the pane management menu, and click-drag to copy text without memorizing a single keybinding.

For keyboard navigation, it uses a classic Prefix modal pattern (default prefix is Ctrl+B—press and release Ctrl+B first, then press the action key, rather than holding Ctrl+B down):

Keybinding Action
prefix + v Split vertically to the right (create right pane)
prefix + - Split horizontally downward (create bottom pane)
prefix + c Create a new Tab inside the current Workspace
prefix + Shift+G Interactively create a new Git Worktree
prefix + ? Toggle the real-time keybinding cheat sheet overlay
prefix + q Detach from the current client view (background tasks continue; closing the window does the same)

Persistence in Practice: Press prefix + q or Cmd+W to close the terminal window at any time → run herdr from any directory to re-attach right where you left off. Only an explicit herdr server stop terminates the background daemon and all running panes.

3.6 Status Light Semantics & Attention Shift

Status Light Lifecycle Meaning Your Action Policy
working Thinking, reasoning, or executing tool calls Ignore—let it run
blocked Stalled on a dangerous-command approval or interactive question, waiting for your keystroke Switch immediately and unblock (highest priority)
idle Turn completed and you have already inspected the pane; standing by Ready for the next prompt
done Task just finished and you have not yet viewed the output (automatically transitions to idle once focused) Switch over when convenient to review results

This state machine transforms daily developer flow: you can keep agents running across three or four repositories while focusing deeply on architecture or documentation, keeping the sidebar in your peripheral vision—ignoring everything except blocked and done.

3.7 Host Terminal Selection & Configuration: Why Tabby Wins

Because herdr is a TUI application running inside a terminal emulator, the host terminal’s event-forwarding behavior directly dictates day-to-day ergonomics.

My daily workflow has two non-negotiable requirements:

  1. Full right-click mouse management for panes: splitting, closing, and zooming panes entirely via the right-click context menu;
  2. Direct Cmd+V clipboard image pasting: pasting error screenshots and architecture sketches straight into multimodal agents like Claude Code.

Testing the major macOS terminal emulators against these two hard criteria yielded a clear winner:

Host Terminal Cmd+V Image Paste into Agent inside herdr Right-Click & Protocol Support Verdict
Tabby (Electron) Works end-to-end (clipboard paste is handled at the app layer without being swallowed by the PTY) 100% passthrough to herdr once Tabby’s native right-click menu is disabled Primary Choice (Zero Compromise)
Ghostty Broken (Cmd+V only delivers a literal "v" character; image pasting fails both inside herdr and in bare CLI) Native Kitty keyboard protocol and mouse passthrough Disqualified for screenshot-heavy workflows
Warp Constrained by custom input box Block input model hijacks mouse and key events, conflicting with TUI multiplexers Incompatible
macOS Terminal.app No rich clipboard image passthrough Lacks Kitty Keyboard Protocol; incomplete modifier key forwarding Not Recommended

Three-Step Zero-Friction Tabby Setup:

  1. Open Tabby Settings → Application, locate “Show menu on right click”, and turn it off (sets rightClick: 'off' in config). Once disabled, right-clicking inside any pane opens herdr’s native split/pane menu;
  2. Recommended typography & theme: Maple Mono NF CN paired with the Catppuccin Mocha color scheme;
  3. Note for Pure Keyboard Users: If you do not rely on Cmd+V image pasting and prefer keyboard-driven workflows, your host terminal must satisfy three requirements: native mouse event passthrough, Kitty Keyboard Protocol support (use Kitty ≥ 0.33 or Alacritty ≥ 0.15.0, as older Alacritty releases suffer from duplicate key-release byte bugs), and mapping macOS Option as Meta.

4. Putting It Together: Project-Level Concurrent Environment Design

4.1 Directory & Session Topology

Combining git worktree with herdr produces a clean, standardized on-disk and in-memory topology for every project:

A single global herdr server hosts all of your active repositories (one Workspace per repo) alongside the concurrent worktree panes underneath each project—giving you a single-pane-of-glass command center across every running agent.

4.2 Five Engineering Design Principles

  1. Bind Workspaces to projects, never to agents: One Git repository maps to one Workspace. Running multiple projects in parallel simply means multiple Workspaces coexisting side by side.
  2. Create Worktrees strictly for concurrency isolation: When a single agent works on a project, run it directly in the main repository without any worktrees. Spin up worktrees only when two or more agents need to modify the same repository simultaneously.

    Hard-earned lesson: Early on, I named directories after agent types (myproject-claude, myproject-opencode). The moment I wanted to run Claude in the second directory, the directory name contradicted the process inside it. A directory should represent “Isolated Copy #N of the repository (wt-1, wt-2)”, completely decoupled from which agent works inside it.

  3. Assign agents on the fly; keep slot numbers agnostic: wt-1 is just a slot index. Whether that pane runs claude for feature work today, codex for bug fixes tomorrow, or opencode for unit tests next week is decided at launch via the command or --kind flag—the directory stays put.
  4. Use the main repository exclusively for convergence: Inside worktrees, agents may only run git commit—never git push. Branch merging, conflict resolution, and remote pushing happen centrally in the main repository (enforcing Section 2.3 at the environment level).
  5. Broadcast untracked configs one-way from the main repo: Treat the main repository as the Single Source of Truth (SSOT) for gitignored files (.env, local keys, MCP configs) and broadcast them into worktree slots via a sync script, solving Section 2.4 cleanly.

6. Architectural Deep Dive: The Three-Tier Orthogonal Agent Stack

As concurrency scales further, terminal split panes alone are insufficient. You must architecturally decouple the Control Plane, Session Layer, and Memory Layer:

Architectural Tier Primary Provider Responsibility Boundary & Primitives
Control Plane herdr Owns PTY pane lifecycles, status light sensing (working/blocked/done), process spawning, and prompt/wait/send-keys scheduling. Note: prompt is a blind string pipe—the control plane is deliberately agnostic to domain semantics
Session Layer Agent CLI Native Storage Persists conversation transcripts on disk scoped by project directory (e.g., Claude Code’s -c to continue the latest session, -r to pick a historical session, --fork to branch a conversation). Switching terminal hosts never loses dialogue history
Memory Layer Semantic Memory Store (e.g., OpenViking) Persists cross-session, cross-agent architectural decisions and post-mortems. Any durable memory system supporting “write to an explicit URI → retrieve via semantic search across sessions” can fulfill this tier

Core Layering Discipline: Never pipe massive blocks of context between agents using blind herdr pane send-keys keystrokes. The clean multi-agent contract is: the Control Plane governs where a task runs and whether it has finished; the Session Layer governs where the current dialogue is; and cross-agent knowledge handoff flows strictly through the Memory Layer (workers write structured conclusions to an explicit memory URI or handoff file, and the primary agent reads them by address).

7. After Hours: End-to-End Mobile Remote Takeover

Once a concurrent multi-agent environment is humming along, the next natural question arises: when you step away from your desk for dinner or hop on the subway, who approves the permission prompt when an agent hits blocked?

Remote desktop apps (VNC, TeamViewer, AnyDesk) are most people’s first instinct—and the worst possible mobile experience. Pinch-zooming a 27-inch desktop on a 6-inch phone screen while full-screen TUI redraws blur into compression artifacts is pure friction. Because the target you want to control is a terminal session, the native protocol for the job is SSH.

8. Production Pitfalls & Troubleshooting Guide

Here is a consolidated troubleshooting checklist distilled from daily production use of herdr:

  1. prefix Keybindings Never Trigger Anything:
    herdr’s prefix key (default Ctrl+B) uses a strict two-stroke sequence—press Ctrl+B and release your fingers completely, then press the action key (such as v, c, or ?). Holding Ctrl+B down while pressing the action key will fail 100% of the time in every terminal emulator.

  2. Lighting Up Status Indicators for Unsupported Agents (e.g., CodeBuddy):
    Take codebuddy as an example: it is absent from herdr 0.9.5’s built-in agent enum, screen-matching manifests, and integration install targets. Moreover, the official docs state that Override manifest rules can only tweak regexes for already-recognized agent kinds—they cannot register a brand-new agent type.
    The official first-class solution is to use the agent’s own lifecycle hooks to call herdr pane report-agent directly:

    Because every herdr pane automatically injects the HERDR_PANE_ID environment variable into child processes, mapping six standard lifecycle events in your agent’s hook config gives you full status light support:

    • SessionStart → --state idle
    • UserPromptSubmit → --state working
    • Stop → --state idle
    • Notification (permission_prompt) → --state blocked
    • Notification (idle_prompt) → --state idle
    • SessionEnd → herdr pane release-agent "$HERDR_PANE_ID"

  3. Two Hidden Traps with herdr machine add:

    • The Default No Prompt Trap: If the remote machine already has a running herdr server, the CLI asks interactively whether to stop and replace it ([y/N]). Pressing Enter accepts the default N, which silently aborts saving the machine registration. You must explicitly type y and press Enter;
    • Daemon Contention: If you previously configured a custom LaunchAgent or systemd unit on the remote machine to keep herdr server alive, it will fight with herdr’s machine replacement logic. Remove custom service wrappers on remote nodes and let herdr’s machine mode manage the server lifecycle natively.

  4. Edge Cases in State Detection & Full-Screen TUI Output Reading:

    • unknown Does Not Mean Finished: An unknown status means the agent process is still running but its current screen state cannot be classified. Run herdr agent explain --json to inspect the exact state-machine evaluation;
    • CLI agent read Does Not Clear the done Light: Only focusing the pane interactively inside the TUI client transitions an agent from done back to idle;
    • Alternate Screen Buffer Truncation: Full-screen TUI agents like Claude Code render inside the terminal’s Alternate Screen buffer. Long responses do not scroll into the standard terminal scrollback buffer, meaning herdr agent read only captures the visible tail on screen. When scripting automated fan-out workflows, always instruct worker agents in their prompt to write full reports to a designated Markdown or JSON file, and have the primary agent read the file from disk rather than scraping the pane.

  5. Logs & Hot-Reload Entry Points:

    • Runtime log files: ~/.config/herdr/herdr*.log
    • Check client/server health and versions: herdr status (or herdr status server / herdr status client)
    • Dump the complete default configuration reference: herdr --default-config
    • After editing ~/.config/herdr/config.toml, run herdr server reload-config to apply changes in milliseconds without restarting the server.
